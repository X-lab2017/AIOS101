# 交互开发需求：我的 AI 开源学习问题地图

> 活动 ID：`ACT-CH01-02`
>
> 学习证据：`EVD-CH01-02`
>
> 状态：待开发，尚未实现或课堂实测
>
> 教学正本：[学生任务单](../../activities/student/ACT-CH01-02.md)
>
> 实施依据：[活动规格](../../activities/ACT-CH01-02-learning-question-map-spec.md)｜[教师指南](../../activities/teacher/ACT-CH01-02.md)

## 一、要解决的问题

帮助学生把一个笼统的 AI 疑问逐步改写为有对象、有证据路径、有下一步行动的问题地图，并在后续章节回查和修订。交互应保留问题变化的过程，而不是只生成一张看起来完整的卡片。

地图是个人学习计划，不是项目事实核查结论，也不证明学生已经完成复现、贡献或创造。

## 二、用户流程

1. **确定对象**：填写 AI 成果或工具名称；版本和状态未知时允许明确选择“未知／待核查”。
2. **指出黑盒**：说明最想理解、核验或改进的一环，以及它为何与学习、学科或社会生活有关。
3. **改写问题**：先保留原始疑问，再改写为可观察、可核查的核心问题。
4. **整理证据**：用卡片或列表选择代码、数据信息、参数、文档、评测、版本、许可、协作记录等候选证据，并说明选择理由和优先级。
5. **选择行动**：确定一种低门槛下一步行动、预期产物和所需条件。
6. **设想贡献**：填写一种非代码贡献设想、潜在受益者和仍需确认的真实需要。
7. **记录边界**：保留未知、待核查和不适用事项，选择准备回查的后续章节。
8. **反馈修订**：记录同伴或教师反馈，修改优先级最高的问题并说明变化。
9. **导出提交**：预览一页问题地图，导出 Markdown 或 JSON，供后续章节继续更新。

## 三、建议数据结构

```text
activity_id: ACT-CH01-02
evidence_id: EVD-CH01-02
schema_version: 1
status: draft | complete
object: {name, version_status, version_or_reason}
black_box: {part, significance}
initial_question: string
core_question: string
evidence[]:
  type
  description
  priority
  availability: known | unknown | to_verify | not_applicable
  reason
priority_reason: string
next_action: {action, expected_output, conditions}
contribution:
  stage: idea | planned
  type
  description
  beneficiaries
  need_to_confirm
unknowns[]: {item, status, verification_idea}
linked_chapters[]: {chapter_id, question_to_revisit}
feedback: {content, source_type}
revision: {before, after, explanation}
ai_disclosure: {used, description}
```

`contribution.stage` 在本章只能是“设想”或“计划”，界面不得显示为已经发生的社区贡献。后续章节如增加真实贡献记录，应使用新的活动与证据字段，不回写伪造本章事实。

## 四、保存、导入与导出

- 默认保存在当前浏览器本地，无需账号，不默认上传或公开问题地图；
- 支持草稿恢复、手动清除、Markdown 与 JSON 导出，以及 JSON 重新导入继续编辑；
- Markdown 同时保留原始问题、核心问题、证据优先级、行动、贡献设想、未知事项、反馈和修订，而非只导出最终卡片；
- 后续章节回查时新增修订记录，不覆盖最初版本；能够查看“问题为何改变”；
- 导出时标明草稿状态和缺项，不生成教师评价或能力达成标识；
- 如未来提供云端共享，必须由学生主动选择，并说明可见范围、保存期限和删除方式。

## 五、分类与反馈规则

- 可用卡片分类或拖拽组织证据和行动，但同时提供按钮、菜单或文本等等效操作，拖拽不得成为唯一方式；
- 所有证据和对象字段均允许“未知”“待核查”“不适用”，不得把未知自动转换成“没有”或“封闭”；
- 自动反馈只检查缺项，提示对象是否具体、问题能否观察、证据是否对应、行动是否可行；
- 不自动判断对象是否开源，不自动给问题质量或贡献价值打分；
- AI 如用于提供改写建议，必须与学生的原始内容清楚区分，由学生决定是否采纳并披露。

## 六、无网络回退、隐私与可及性

- 无脚本、交互加载失败或低性能设备上，直接提供[学生任务单](../../activities/student/ACT-CH01-02.md)作为等效路径；
- 地图默认仅本人可见，教师查看或公开展示须按课程安排由学生主动提交；
- 不要求写入私人对话、个人敏感信息、真实社区身份或未经许可的数据；
- 支持窄屏和移动端，卡片信息不依赖颜色或位置才能理解；
- 支持键盘完成分类、排序、编辑和导出，屏幕阅读器能够读出字段标签、优先级、状态和错误；
- 拖拽、动画和自动建议均可跳过，不影响核心学习成果。

## 七、验收测试

- [ ] 从对象到导出可完成全流程，原始问题、黑盒、核心问题、证据、行动、贡献设想、未知、回查章节、反馈、修订和披露均未遗漏；
- [ ] 刷新后恢复本地草稿，清除操作需要确认且确实生效；
- [ ] Markdown、JSON 与页面字段一致，JSON 可重新导入，后续修订不会覆盖原始问题；
- [ ] “未知／待核查／不适用”能保存和导出，不会被改写成“没有”；
- [ ] 贡献始终标为设想或计划，不产生虚假社区贡献事实；
- [ ] 无网络、禁用脚本或组件失败时能够使用等效学生任务单；
- [ ] 不默认上传或公开，本地数据范围和清除方式有说明；
- [ ] 窄屏、键盘和屏幕阅读器可完成分类与排序，拖拽不是唯一路径；
- [ ] 自动反馈不产生开源认定、成绩或能力达成结论。
