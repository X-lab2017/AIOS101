## 1. 章节定位

### 1.1 核心问题

已经训练好的模型怎样根据输入逐步生成输出？为什么同一模型可能产生不同回答，系统配置与资源约束怎样影响表现，我们又应依据什么证据评价它？

### 1.2 本章价值

CH04 解释模型参数怎样形成，本章转入模型形成后的运行过程。章节把“模型计算”“生成策略”“运行系统”“评价证据”连成一条链，帮助学习者区分模型能力、单次输出和系统表现，避免用一个回答或一个榜单分数作全面判断。它为 CH06 的检索与工具系统提供推理和评估基础，也为 CH08 的复现分析提供配置记录意识。

### 1.3 目标学习者

面向所有学科背景的大学生，不要求编程或部署经验。需要 CH04 的参数、训练目标和数据划分基础，但不要求会推导模型公式。针对“推理就是像人一样逻辑思考”“模型每次必然给同样答案”“分数高就适合所有任务”“服务慢只是模型不好”等误解提供支架。

### 1.4 建议学习时间

| 部分 | 建议时间 | 说明 |
|---|---|---|
| 教材学习 | 90—110 分钟 | 生成过程、系统约束、评价设计与真实案例 |
| 课堂活动 | 45—60 分钟 | 后续独立讲义设计 |
| 探究实践 | 60—90 分钟 | 推理或评估对照实验，提供静态结果回退 |
| 反思与修订 | 20—30 分钟 | 检查变量、配置、样本与结论边界 |

### 2.3 常见误解与诊断

| 常见误解 | 形成原因 | 诊断问题／任务 | 纠正方式 |
|---|---|---|---|
| 推理等于继续训练 | 都涉及模型计算 | 生成回答时参数是否因每次提问自动更新？ | 区分参数使用与参数更新，持续学习另行说明 |
| 推理就是人的逻辑思考 | reason 一词多义 | 本章 inference 指什么计算过程？ | 区分技术运行与回答中的推理行为 |
| 同一模型必然输出相同答案 | 忽略采样和系统条件 | 哪些设置与上下文可能变化？ | 做单变量对照，不假设产品配置固定 |
| 输出越长或越流畅就越正确 | 把表达质量当事实质量 | 怎样核查任务正确性？ | 指标与任务匹配，保留人工或外部证据核查 |
| 一个榜单可代表全部能力 | 忽略任务覆盖与配置 | 哪些任务没有被测量？ | 建立评价矩阵和结论边界 |
| 服务速度只由参数量决定 | 忽略系统与负载 | 引擎、硬件、批处理和网络扮演什么角色？ | 分层分析，不以单一指标推断全部系统 |

## 4. 内容范围与边界

### 4.1 必须覆盖

- 推理的技术含义及与训练的区别；
- 以完整新生导言情境解释输入、系统提示、历史上下文、模型计算、逐 token 生成和输出；
- 上下文长度、最大生成长度和实际输出长度的区别；
- 贪心、采样、温度、top-k 与 top-p 的概念性解释，生成 top-k 与第六章检索 top-k 的场景区别；
- 模型、推理引擎、服务、硬件和使用情境的系统分层；
- 首 token 等待、完整回答时间、吞吐、并发、负载、排队、超时与流式输出的区别，不做工程优化教程；
- 任务、样本、指标、基线、配置、重复试验和失败样例组成的最小评价；
- 自动指标与人工判断的适用范围，EM、Correct、Acc、F1、精确率和召回率的通俗解释；
- 公开评测的版本、自报、复算、污染、覆盖、平均结果与失败分布、单次成功与多次采样的结论边界。

### 4.2 可选拓展

- 对同一开放小模型开展有限次生成对照；
- 比较两种推理配置或一个公开模型的多次输出；
- 阅读真实推理项目文档，观察配置与兼容声明；
- 设计面向本专业任务的小型评价集。

## 5. 建议内容结构

1. **问题导入**：同一模型为何给出不同回答；
2. **推理过程**：从输入到逐 token 输出，区分训练、预填充与解码；
3. **生成变量**：上下文、贪心、采样、温度、top-p 与长度限制；
4. **公平对照**：控制变量、固定配置、随机性、重复与失败记录；
5. **系统分层**：模型、推理引擎、服务、硬件、网络与使用情境；
6. **真实运行解剖**：DeepSeek-R1 的 vLLM 示例及 vLLM 的系统功能；
7. **最小评价**：任务、样本、指标、基线、配置、重复与失败；
8. **公开评测解剖**：DeepSeek-R1 的设置、四类任务、代表数值和证据边界；
9. **承接下文**：当模型需要外部知识和行动能力时，进入 CH06。

## 7. 教材与讲义规格

### 7.1 教材正文

- 预期篇幅：约 12000—16000 中文字；增加篇幅必须用于背景、概念解释和真实情境，不用于扩展工程调优；
- 必须自足解释推理、预填充、解码、生成配置、系统分层、延迟、吞吐与最小评价；
- 必须在正式定义前后提供非技术读者可理解的情境、简化示例或类比，并指出类比与示意数字的边界；
- 必须具体解释候选分布、top-k 与 top-p、流式输出、API、并发、首 token 与完整响应延迟和吞吐，不以术语定义代替理解支架；
- 推理引擎命令和并行配置标为进阶阅读，核心学习不得依赖掌握命令、显存算法或硬件部署；
- 必须使用来源：`SRC-2026-016`、`SRC-2026-017`、`SRC-2026-024`；
- 必须自足呈现 DeepSeek-R1 的最大生成长度、温度、top-p、每题响应数、多次测试建议、四类评测任务及代表数值；不得要求读者另查表格才能理解；
- 必须区分上下文长度、最大生成长度、输出 token 数和实际输入长度；
- 必须提供七幅 Mermaid 结构图和两项 DeepSeek-R1 固定材料截图占位，图号按出现顺序排列；
- 必须解释 EM、Correct、Acc、F1 及其适用边界；解释 F1 时同时解释精确率和召回率，不以缩写代替定义；
