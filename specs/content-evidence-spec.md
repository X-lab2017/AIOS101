# 内容与证据规范

> 版本：v0.1
> 适用范围：教材、讲义、活动、图表、案例、数据分析、教师指南及公开发布内容。

## 1. 基本原则

1. **服务学习成果**：内容深度以支持理解和创造为准，不以覆盖所有知识点为目标。
2. **证据与观点分离**：事实、数据、案例、观点和预测必须能够被读者识别。
3. **具体对象与版本**：评价模型、项目、工具或社区时，尽量落实到具体版本和日期。
4. **保留结论边界**：明确证据不能支持什么，不把相关、排名或可见性直接解释为因果、质量或公共价值。
5. **公开可核验**：引用、数据、图片、代码和修改记录应允许他人回查。
6. **可持续维护**：稳定原理与时效案例分开，避免整章对单一工具版本形成不必要依赖。

## 2. 内容表达标准

### 2.1 章节叙述

- 从真实问题或认知冲突开始，先建立心智模型，再引入术语和技术细节；
- 首次出现的重要术语应给出通俗解释，必要时再给出英文和正式定义；
- 不使用名词堆砌制造深度，不用复杂公式代替概念解释；
- 公式、代码和系统图必须服务于一个明确问题；
- 每个案例都应说明其教学用途，而不是只作为“最新进展”展示；
- 每章结尾应回答核心问题，并指出仍未解决或需要继续探究的问题。

### 2.2 通识与严谨

- 通识化主要减少不必要的前置知识和工程门槛，不得删除关键证据和限定条件；
- 类比可以使用，但必须指出类比失效的地方；
- 进阶内容应置于明确标记的拓展区，不得改变核心叙述的平均难度；
- 对非技术学生的任务应保留分析、判断和创造要求，不能退化为被动观看。

### 2.3 常见表述边界

| 不严谨表述 | 应改为 |
|---|---|
| “下载量证明模型被广泛使用” | “下载量反映特定平台和时间窗口内的获取信号” |
| “公开权重就是完整开源 AI” | “需分别核查材料、许可、版本和复现条件” |
| “排名第一说明技术最好” | “排名只在指定指标、样本和榜单深度内成立” |
| “派生关系证明正式合作” | “派生声明提供复用线索，合作与贡献回流需另行核验” |
| “开源必然带来公共价值” | “开放提供条件，公共价值需结合使用、维护和受益证据判断” |
| “实验成功证明方法普遍有效” | “结果仅在所述环境、输入和评估范围内成立” |

## 3. 信息类型与证据要求

| 类型 | 写作要求 | 最低证据 |
|---|---|---|
| 事实 | 可回查到原始来源，避免多手转述 | 官方文档、标准、论文、原始仓库等 |
| 数据 | 说明对象、时间、样本、单位和计算方法 | 数据文件、图表口径、来源与处理记录 |
| 案例 | 说明选择原因、版本和适用范围 | 案例材料、选择依据、核验日期 |
| 观点 | 明确作者或分析立场，不伪装成共识 | 论证过程、反方观点或讨论问题 |
| 预测／前瞻 | 使用条件性表达，不列为已实现事实 | 假设、趋势依据、可观察信号 |
| 模拟／示意 | 就近标注，不进入实测统计 | 模拟目的、生成方式、与实测的区别 |

## 4. 来源规范

### 4.1 来源优先级

优先使用：原始标准与官方文档、原始论文、项目仓库与固定提交、原始数据集、正式报告、可信机构出版物。新闻报道、博客和二手总结可用于线索与背景，但关键结论应尽量回到原始来源。

### 4.2 来源登记

每项支持关键结论的来源必须进入[来源登记表](source-register.md)，至少记录：

- 来源 ID、标题、作者／机构、URL 或出版物信息；
- 页面、章节、图表、提交号或其他定位信息；
- 发布日期、读取日期、版本或快照日期；
- 用于支持的章节与具体结论；
- 许可、署名和再使用条件；
- 核验状态、核验人和未决问题。

### 4.3 引用呈现

- 引用应紧跟其支持的句子、段落、图表或数据；
- 不得用一个来源支持其并未直接说明的扩展结论；
- 直接引用保持原文，改写不得改变原意；
- 链接失效时应保留出版物信息、版本和可用存档；
- 不得引用未实际阅读或无法核验的内容。

## 5. 数据与图表规范

任何数据结论必须根据适用情况说明：

1. 统计对象与单位；
2. 平台、地域和样本覆盖；
3. 统计期、读取日和快照日；
4. 分子、分母与缺失处理；
5. 去重、归属、转换、聚合与算法版本；
6. 观测、派生、模拟或预测状态；
7. 可复现材料及实际复算程度。

图表必须具有标题、单位、时间、来源和必要注释。不得通过截断坐标、选择性样本或视觉编码制造超出数据的结论。

## 6. 技术与复现规范

- 命令、代码和配置应标明运行目录、环境、依赖和版本；
- 已运行、部分运行、仅阅读、待核验必须分别标注；
- 实验结果应记录输入、输出、失败和必要的环境差异；
- 使用第三方项目时固定提交或版本，不把“源码存在”写成“实验已完成”；
- 无 GPU、无账号或平台不可用时应提供冻结结果、快照或缩小任务的替代路径；
- 公开密钥、个人信息、受限数据和敏感内容不得进入仓库或教学材料。

## 7. AI 辅助内容生产

AI 可用于资料整理、草稿、代码、图表、翻译和校验，但必须遵守：

- 人类作者对最终内容、引用和结论负责；
- 不得使用虚构来源、虚构数据、虚构运行结果或虚构社区贡献；
- 关键事实和技术步骤必须人工或工具核验；
- 对 AI 生成内容进行许可、隐私、偏见和安全检查；
- 重要章节在规格中记录 AI 的协作角色及需要人工复核的部分；
- 不因生成速度快而绕过规格评审和验收门禁。

## 8. 许可与署名

- 每个外部文本、图片、数据、代码和模板都应核查许可与署名要求；
- 第三方材料保留其原有许可，不因收录自动改变；
- 修改外部素材时说明修改内容；
- 对无法确认再使用条件的材料，不直接复制发布，可改为链接、重述或自制；
- 课程自身资源的许可由仓库维护者统一决定，不在单个文件中设置冲突条款。

## 9. 内容验收清单

- [ ] 核心概念准确，类比和简化没有造成误导；
- [ ] 关键事实与数据均有来源和定位；
- [ ] 时效内容具有日期与版本；
- [ ] 数据口径和图表注释完整；
- [ ] 技术步骤的核验状态真实；
- [ ] 观点、预测和模拟得到明确标识；
- [ ] 外部素材许可与署名完整；
- [ ] 结论没有超出证据范围；
- [ ] 内容与对应章节规格和学习成果一致。
