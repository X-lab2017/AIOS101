# 验收与发布规范

> 版本：v0.1
> 适用范围：规格、章节、活动、配套资源、课程版本与变更验收。

## 1. 验收原则

1. **以规格为依据**：验收检查事先约定的成果和条件，不临时改变标准。
2. **以证据为准**：完成声明必须对应文件、记录、运行结果、评审意见或其他可回查证据。
3. **分层验收**：规格批准、产物完成、教学可用和正式发布是不同状态。
4. **不以合并代替验收**：代码或文档进入主分支，不代表学习成果和技术质量已自动通过。
5. **问题透明**：未验证、未覆盖和阻塞项必须记录，不得用平均印象掩盖关键失败。

## 2. 就绪定义（Definition of Ready）

一个工作项进入实质生产前，必须：

- [ ] 能追溯到课程宪法和课程总规格；
- [ ] 有唯一 ID、负责人和当前状态；
- [ ] 目标学习者、学习成果和范围明确；
- [ ] 非目标和内容边界明确；
- [ ] 学习产物与评价证据明确；
- [ ] 核心活动具有低门槛路径；
- [ ] 关键来源和实施依赖已识别；
- [ ] 验收条件完整且可以检查；
- [ ] 影响其他规格或产物的事项已列出；
- [ ] 规格状态已转为“已批准”。

## 3. 完成定义（Definition of Done）

一个章节或活动称为“完成”，必须：

- [ ] 规格中承诺的下游产物齐全；
- [ ] 学习成果、活动、产物与评价形成闭环；
- [ ] 核心通识和分层实践路径可用；
- [ ] 内容、证据、许可、展现和协作规范检查通过；
- [ ] 技术步骤按声明程度实际核验；
- [ ] 已执行评审并处理阻塞问题；
- [ ] 已保存验收记录和必要证据；
- [ ] 版本、变更和未决项已更新；
- [ ] 无影响学习者使用的未解决严重问题。

## 4. 质量门禁

| 门禁 | 核心检查 | 最低证据 | 不通过示例 |
|---|---|---|---|
| G0 基线 | 上游规格、ID、状态和负责人明确 | 规格元数据与链接 | 无上游依据的独立讲义 |
| G1 定位 | 服务课程定位，不发生隐性漂移 | 定位检查记录 | 变成工具训练或工程专题 |
| G2 成果 | 成果、活动、评价一一对应 | 对齐矩阵与学习证据 | 只写“了解”“掌握” |
| G3 分层 | 全体学习者可进入，进阶不抬高门槛 | 无代码／低代码路径 | 核心成果必须依赖 GPU |
| G4 证据 | 来源、数据、版本、结论边界真实完整 | 来源登记与核验记录 | 虚构引用、未标日期的数据 |
| G5 产物 | 教材、讲义、活动和评价一致且完整 | 文件清单与一致性检查 | 讲义任务与教材概念冲突 |
| G6 可用 | 技术、视觉、可及性和替代路径经过检查 | 运行记录、预览、检查表 | 命令不可运行、图表无法辨认 |
| G7 发布 | 版本、许可、变更和遗留问题明确 | 发布记录与变更日志 | 无版本、无许可、未披露阻塞项 |

## 5. 分类验收要求

### 5.1 规格验收

- 范围和非目标是否明确；
- 学习成果是否可观察；
- 活动是否产生相应证据；
- 评价是否测量目标成果；
- 验收条件是否可执行；
- 未决项是否阻塞生产。

### 5.2 教材与讲义验收

- 核心问题是否贯穿；
- 概念和术语是否一致、准确、可理解；
- 来源、图表、许可和边界是否完整；
- 讲义是否支持课堂学习而非复制正文；
- 内容更新是否同步所有派生格式。

### 5.3 活动验收

- 最低环境是否可行；
- 输入、步骤、产物、量规和降级路径是否齐全；
- 是否包含观察、比较、核查或解释；
- 是否保留失败与过程证据；
- 安全、隐私、成本、许可和社区风险是否处理。

### 5.4 技术资源验收

- 按声明范围执行构建、运行或测试；
- 记录环境、命令、输入、输出和失败；
- 未运行部分明确标记；
- 结果可回查，敏感信息未泄露；
- 外部版本和依赖已固定或有更新策略。

## 6. 问题等级与发布规则

| 等级 | 定义 | 示例 | 发布规则 |
|---|---|---|---|
| 阻塞 | 导致核心目标错误、资源不可用或严重风险 | 虚构数据、核心实践无法完成、许可禁止发布 | 必须修复并重新验收 |
| 严重 | 显著影响学习成果或多个产物一致性 | 核心概念错误、评价无法测量成果 | 原则上修复后发布 |
| 一般 | 有明确局部影响但存在可接受替代 | 个别链接失效、局部排版问题 | 可记录后发布，须给期限 |
| 建议 | 不影响当前使用的改进 | 表达优化、额外案例 | 进入后续迭代 |

任何“带问题发布”必须记录问题、影响、临时措施、负责人和修复期限。

## 8. 发布检查

- [ ] 对应规格状态为“已验收”；
- [ ] 发布包内容完整，入口清晰；
- [ ] 版本、日期和变更记录已更新；
- [ ] 来源、许可和署名检查通过；
- [ ] 敏感信息和受限材料检查通过；
- [ ] 教材、讲义、网站、活动与评价版本一致；
- [ ] 已知问题和适用范围公开说明；
- [ ] 后续维护、勘误和反馈入口可用。

## 9. 发布后迭代

- 收集学习成果证据、学习者反馈、技术故障和社区建议；
- 区分内容错误、规格缺陷、实施困难和新增需求；
- 影响定位或成果的问题进入变更流程，不以零散补丁长期堆积；
- 新版本发布前复核旧问题是否真正关闭；
- 保留历史版本和验收记录，支持课程改进的纵向比较。
