# 学习评价规范

> 版本：v0.1
> 上游依据：课程宪法、课程总规格
> 适用范围：章节活动、形成性评价、综合项目、团队任务与课程验收。

## 1. 评价目的

评价用于判断学习成果是否达成、提供可行动的反馈并促进修订，而不是单纯排序或检查任务完成数量。

必须坚持：

- **成果对齐**：评价测量对应学习成果，而非无关的记忆、设备条件或工具熟练度；
- **证据优先**：以产物、过程、解释、反馈和修订构成证据链；
- **过程可见**：保留重要尝试、失败、判断和版本变化；
- **多路径等效**：无代码、低代码和进阶路径可以不同，但核心成果标准不得无故降低；
- **公平可及**：不因设备、专业背景、公开意愿或社区语言造成不合理障碍；
- **反馈促学**：重要任务至少提供一次依据量规的反馈与修订机会。

## 2. 学习成果与评价证据

| 成果 | 必须观察的能力 | 不足以单独证明达成的证据 |
|---|---|---|
| LO1 系统理解 | 解释组成、关系、机制与边界 | 术语默写、概念图美观 |
| LO2 开放判断 | 针对版本核查材料、许可与维护证据 | 只抄许可证名称、只下载模型 |
| LO3 技术探究 | 提出假设、操作观察、比较结果、解释失败 | 命令运行成功截图 |
| LO4 数据研究 | 核对口径、分析数据、形成有边界的结论 | 复制报告图表或排名 |
| LO5 协作贡献 | 遵循规范、有效沟通、回应反馈并改进 | Star、Fork、无实质内容的 PR 数量 |
| LO6 负责任创造 | 组合资源、形成产物、评估风险并支持复用 | 仅展示 Demo、页面精美 |

## 3. 评价类型

### 3.1 诊断性评价

用于识别前置知识、误解和学习路径，不应因起点差异惩罚学生。可采用预测、概念图、短任务或自我评估。

### 3.2 形成性评价

贯穿章节学习，至少包括：

- 学习过程中的提问、观察或草稿；
- 基于明确标准的自评、互评或教师反馈；
- 一次有记录的修订；
- 对未达成成果的补充学习路径。

### 3.3 总结性评价

用于判断章节或课程成果达成度，必须结合产物和解释。不得以一次客观题考试替代全部课程成果评价。

## 4. 通用四级量规

| 等级 | 通用描述 | 证据特征 |
|---|---|---|
| 0　未达成 | 未形成可识别成果，或成果与任务无关 | 缺失、抄袭、虚构或无法说明来源 |
| 1　基本达成 | 能完成主要任务，但理解、证据或独立性存在明显缺口 | 产物基本可用，过程或解释不完整 |
| 2　良好达成 | 能独立完成任务，概念准确，证据充分，结论基本有边界 | 过程完整，来源清楚，能够解释结果并修订 |
| 3　卓越表现 | 能迁移方法、处理复杂性并形成对他人有价值的成果 | 证据可复核，产物可复用，能回应反馈并识别深层限制 |

具体活动必须将通用描述改写为与任务直接相关的可观察标准。

## 5. 综合项目评价维度

综合项目至少从以下维度评价，权重在课程实施规格中确定：

| 维度 | 核心问题 | 对应成果 |
|---|---|---|
| 问题与理解 | 是否明确真实问题并准确使用核心概念 | LO1 |
| 开放与许可 | 是否核查材料、权利、版本和署名 | LO2 |
| 探究与方法 | 是否有合理过程、对照、失败记录与解释 | LO3 |
| 数据与证据 | 是否口径清楚、结论受证据支持 | LO4 |
| 协作与贡献 | 是否有效沟通、回应反馈并识别个人贡献 | LO5 |
| 产物与复用 | 是否可访问、可使用、可复现或可继续建设 | LO6 |
| 责任与公共价值 | 是否说明风险、限制、受益对象和未验证事项 | LO2、LO4、LO6 |

不得只用“展示效果”覆盖上述维度。

## 6. 团队与个人评价

- 团队任务必须同时提交团队产物和个人贡献档案；
- 个人评价可依据任务记录、版本历史、口头解释、同伴反馈和个人反思；
- 不得把提交次数或代码行数直接等同于贡献质量；
- 文档、数据、评测、设计、翻译、组织和社区沟通均可构成有效贡献；
- 贡献冲突应先查看证据并听取当事人说明，不采用自动化分数直接裁决。

## 7. AI 使用与学术诚信

### 7.1 允许的使用

在章节或活动规格允许的情况下，AI 可用于检索线索、解释概念、辅助编程、修改表达、生成测试和获得反馈。

### 7.2 必须披露

学生应说明：

- 使用了哪些 AI 工具及主要用途；
- 哪些部分由 AI 生成或显著修改；
- 自己如何验证事实、代码、数据与结论；
- 最终判断和修改由谁完成。

### 7.3 禁止行为

- 虚构来源、数据、实验结果、社区反馈或个人贡献；
- 将 AI 生成内容未经核验直接作为本人分析提交；
- 上传受限数据、个人信息、密钥或无权公开的材料；
- 使用 AI 制造无实质内容的社区贡献或干扰真实项目；
- 隐瞒任务明确要求披露的重要 AI 使用。

评价重点是学习者的理解、验证和责任，而不是简单检测文本是否像 AI 生成。

## 8. 反馈与修订

反馈应具体指向量规和证据，包括：

1. 已达成的部分；
2. 尚未达成的成果；
3. 证据或方法中的关键缺口；
4. 可执行的下一步；
5. 修订后需要重新提交的证据。

修订不得只润色外观而回避概念、数据或方法问题。

## 9. 公平与可及性

- 为设备、网络、算力或账号受限者提供等效路径；
- 不愿公开个人信息者可使用匿名、班级内发布或模拟评审，并明确证据性质；
- 语言、视觉、听觉或操作障碍应通过替代格式与合理调整处理；
- 进阶任务的额外表现不得掩盖核心成果未达成；
- 评价者应避免把专业背景、英语表达或社区知名度当作能力替代指标。

## 10. 评价验收清单

- [ ] 每项评价均对应明确学习成果；
- [ ] 量规描述可观察，学生能在任务开始前理解；
- [ ] 核心证据不依赖单一设备或高门槛工具；
- [ ] 过程、产物、解释和修订得到合理评价；
- [ ] 团队任务具有个人贡献识别方式；
- [ ] AI 使用、披露和禁止事项明确；
- [ ] 评价者能够依据相同标准作出基本一致判断；
- [ ] 考核权重与实施参数已在上级规格中明确。
