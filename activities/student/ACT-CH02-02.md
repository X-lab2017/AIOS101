# 学生任务单：设计一次有效贡献——从善意到可评审

> 对应教材：第 2 章
>
> 建议时间：35—45 分钟
>
> 完成方式：个人设计，可独立进行维护者视角自评；课堂上可结对角色评审后修订
>
> 最终提交：一份模拟贡献方案与公共价值说明

**本活动全部为模拟。不要向真实项目提交 Issue、Pull Request 或私信，也不要把课堂方案写成已经发生的社区贡献。**

## 一、你要学会什么

完成活动后，你应能够：

- 从项目需要而不是个人展示出发，选择一项小贡献；
- 写出让他人能够理解、检查和评审的贡献说明；
- 根据维护者反馈作出有理由的回应与修订；
- 区分预期公共价值、可观察证据和仍不能证明的结果。

## 二、虚构项目情境

“校园 AI 学习助手资料包”已经提供核查指南、学科示例、评测题、版本说明和贡献指南。项目希望帮助不同专业的新生检查 AI 回答，不希望把资料变成宣传某个 AI 产品的教程。

项目当前材料：

- 核查指南 v1.2；
- 学科示例集 v1.0，目前以理工科示例为主；
- 新手评测题 v1.1；
- README、许可与材料来源说明；
- 贡献指南和模拟讨论记录。

### 项目贡献规则

1. 先说明需要、受影响者和已查看的材料；
2. 一次贡献集中解决一个小问题，避免同时重写多个文件；
3. 提交说明包括拟修改内容、材料来源、检查方式和 AI 使用；
4. 不提交私人对话、敏感信息、真实学生作业或无权发布的材料；
5. 维护者可要求补充、缩小范围或不接纳，贡献者应说明回应；
6. 文档、数据、评测、翻译、设计、讨论和代码都可以成为贡献。

### 候选需要

你也可以提出符合规则的其他需要。

- 新生反映 README 中“开放材料”“版本”“评测”几个词难以理解；
- 文科学生认为现有示例不足以帮助他们识别虚构引文；
- 有学生希望提供译文，但需要明确翻译范围和检查方式；
- 评测题缺少填写说明，教师难以判断学生是否真正理解；
- 项目没有清楚说明使用 AI 辅助整理示例时应当披露什么。

### 3. 写贡献说明

把你的方案整理成一段 150—250 字的模拟贡献说明，至少包含：

- 项目情境与需要；
- 拟交付内容；
- 材料来源与许可注意事项；
- 自查方式；
- AI 使用披露。

## 四、进行一次模拟维护者评审

**独立学习路径**：暂时放下贡献者身份，把自己设想为需要长期维护该项目的评审者。先只阅读项目规则和你的贡献说明，再逐项写下意见。至少提出一条实质修改要求，并保留“初稿—自我评审—修订稿”。这种模拟自评不能写成真实维护者反馈。

**课堂路径**：请同伴扮演维护者，使用同一张表评审。评审不是判断“我喜欢不喜欢”，而是检查方案是否适合项目。

| 评审问题 | 模拟维护者意见 |
|---|---|
| 需要是否真实、具体，并与项目目标一致 |  |
| 范围是否足够小，交付物是否清楚 |  |
| 是否提供了足够的情境、来源和检查方法 |  |
| 是否增加不必要的维护成本 |  |
| 是否存在许可、隐私或误导风险 |  |
| 最希望贡献者修改的一件事 |  |

评审来源：维护者视角自我评审／同伴角色评审／教师评审。

模拟决定：接纳／要求修改后复审／暂不接纳。

该决定只属于学习活动中的模拟评审，不代表任何真实项目立场。
