# 内容迭代与工程维护指南

版本：v0.2；2026-10-29。适用于当前图文阅读版。先看[当前状态](STATUS.md)；课程目标、成果和评价仍由[课程总规格](../specs/course-spec.md)约束。

## 1. 找到唯一编辑入口

| 要改什么 | 正本与联动 |
|---|---|
| 序言、章节、附录 | `textbook/preface.md`、`textbook/chapters/`、`textbook/appendices/`；构建生成全文、目录、检索、阅读估时和版本摘要 |
| 目标、边界、任务或评价 | 先改对应章节／活动规格，再检查正文、学生／教师材料与派生产物 |
| 插图 | 正文图题和图注＋`textbook/assets/figures/manifest.json`＋图像及源文件；重建 `INDEX.md` |
| 事实与外部材料 | 正文来源与 `specs/source-register.md`；固定版本、读取日和核验范围保持一致 |
| 网页 | `site/` 与 `scripts/build_site.py`；不维护第二份网页正文 |
| 品牌 | 从 `brand/` 复用；固定资产有哈希检查，不因改正文而重绘或更换品牌 |
| 当前进度 | `docs/STATUS.md` 与对应 Issue；结束轮次进入历史记录，不覆盖旧验证事实 |

新章使用唯一 `CHxx-*.md`，先补相应规格。主分支中的正文会被自动发布为可读内容，“草稿”元数据不会阻止上线；暂不准备公开阅读的内容留在工作分支／PR。公共分支也不能保存受限材料。

## 2. 正文与图版契约

- 首行为一级标题，保留“> 版本：”“> 状态：”；章号、CH／ACT／EVD／SRC ID 稳定。首次术语给出背景和解释，示例与实测分开。
- 二级标题构成目录与小节锚点。更名会改变锚点，需检查旧链接、正文交叉引用和跳转；不能把标题更名当成仅排版修改。
- 正文图片使用 `![图 0-4　图题](../textbook/assets/figures/AIOS101_Fig-00-04_opendipper-global_v01.webp)`；紧邻图注使用 `图 0-4　图题。说明与来源`。图号后的全角空格是规范图注标识，正文中的“图 0-4 展示……”保持正文字号。
- manifest 维护 ID、图题、文件、尺寸、字节数、alt、显示宽度和来源；需要时添加 `zoomFile`、`originalFile` 与 `zoomHint`。正文图、图注、索引和放大页必须一致。
- 仅处理确有学习用途的图片。概念插画可使用现实材料和手绘隐喻；精确数值、机制和关系用可核验矢量；真实截图不得生成式改写数据、节点、地图或文字。
- 网页使用适量压缩 WebP，保留宽高比；密集证据提供矢量放大或原图。原始截图、提示及变换过程进入来源记录，不将原图压缩视为重新核验事实。
- 已退出正文的图号不复用。当前退出图、旧矢量与源材料保留是为了溯源和重现，不纳入 Pages 当前图版；不要批量删除清单外文件。
- Markdown 渲染器支持常见段落、标题、简单列表、表格、链接、代码和图版；复杂公式、嵌套或新组件须预览确认，不能假定完整支持所有扩展。

## 3. 日常检查与预览

```bash
python scripts/figures/catalog.py --write
python scripts/sync_status.py --write
python scripts/check_all.py
python -m http.server 8000 --directory dist
```

浏览器打开 `http://localhost:8000/`。窄屏辅助页为 `/review/narrow.html?chapter=PREFACE` 或 `?figure=0-4`，检查 320px／390px 容器；这不等于实体手机测试。

检查变更正文、图注、原图入口、目录、字号、主题和上下章；图像两倍放大应在图内滚动，正文不应横向溢出。首页图片从稳定图号读取当前清单，不再另写一份文件名。正文改图后仍须看首页卡片。

统一检查包含品牌包、状态清单、构建、正文摘要、图版身份、相对链接、安全渲染、阅读界面与旧学习数据逻辑。普通构建无需重新生成图像；额外生成依赖见[脚本说明](../scripts/README.md)。

## 4. 提交、发布与交接

1. 记录目标、依据、影响文件与验收条件，先检查相关 Issue；实质范围变更先改规格。
2. 检查本地未提交文件与远程 main；使用小步提交。已有维护授权范围内继续执行，不重复索要同一授权；新外部行为遵循协作规范。
3. 运行统一检查，审查差异与新增二进制。不要使用盲目的 `git add .` 混入其他人的封面、实验或临时文件。
4. 合并或推送后核对实际远程 SHA；Actions 使用该 SHA 构建正文、CSS／JS 与固定来源链接。PR 只运行检查，不自动创建在线预览。
5. 核对 build 与 deploy 成功，再打开实际 Pages 验收改动。CI 成功不能替代页面检查，更不能替代教学评审。
6. 在工作项中写明提交、运行链接、已验证范围、未验证项和下一步；更新当前状态与必要历史索引。文档也由 CI 检查。

发生并行提交时重新读取远程差异并整合，不强推覆盖。回滚优先用明确的 revert 提交；旧文件恢复使用固定历史提交，不重建整份旧仓库覆盖当前内容。

## 5. 交互、课件与打印版的边界

当前网站不加载手账、活动或进度脚本，不访问旧 `aios101.learning.v1/v2` 数据。原任务单与兼容逻辑保留；恢复交互要先说明具体学习需求、旧数据迁移和验收方式，不能仅因代码存在便重新挂载。

授课稿与 PDF 是派生产物，须标明来源提交、版本与审核状态。当前旧导出已清理，最新正文尚无同步打印版。后续正式导出前确定封面与素材条件，导出后检查图数、目录、分页和小字清晰度，再交付；不得把旧 PDF 的页数与排版报告套用于新正文。

## 6. 教学核验

独立阅读时能否理解概念、跟随例子、区分证据与推断，需要真实学习者试读。建议按章记录卡点、误解、修改理由和反馈；不以页面数、填写率或自动测试数量代替学习成果。学时、评价权重与统一许可等未决项见当前状态和课程规格。
